# QRチケットデータ構造最適化 設計ドキュメント

## 1. 目的

QRチケットのデータ構造をJSON形式から区切り文字形式（パイプ `|`）へ移行し、ペイロードサイズを削減することで、QRコードの読取精度を向上させる。

## 2. 背景

現在のJSON形式（例: `{"e":"...","s":"...",...}`）は、構造上のオーバーヘッドが大きく、特に日本語入力時にQRコードの密度が高くなりすぎる問題がある。これにより、低解像度のカメラや画像アップロードでのデコード失敗が発生している。

## 3. 設計内容

### 3.1. データフォーマット

以下の固定フィールド形式を採用する。

```text
eventId|ticketId|timestamp|name|category|signature
```

| 位置 | フィールド名 | 説明                           | 例           |
| :--- | :----------- | :----------------------------- | :----------- |
| 1    | eventId      | イベントID                     | `T-00001`    |
| 2    | ticketId     | チケットID                     | `T-00003`    |
| 3    | timestamp    | 有効期限（Unixタイムスタンプ） | `1777287600` |
| 4    | name         | 参加者名（任意）               | `山田たろう` |
| 5    | category     | 料金区分（任意）               | `一般`       |
| 6    | signature    | ECDSA P-256 署名 (Base64URL)   | `MEUC...`    |

### 3.2. 制約事項

- **互換性**: 既存のJSON形式QRコードとの互換性は維持しない（新しいパースロジックのみを実装）。
- **区切り文字の保護**: 入力値に含まれる `|` は、署名・生成前に半角スペースに置換する。
- **日付形式**: ISO 8601から秒単位のUnixタイムスタンプに変更。検証時は `timestamp * 1000` でDateオブジェクトに変換する。
- **データ量制限**: 160pxの表示サイズでの読取精度を確保するため、**署名・タイムスタンプ等を含む全データ** の合計を **300バイト以内**（UTF-8）に制限し、生成時にバリデーションを行う。
- **UIフィードバック**: チケットリストの各行に現在の合計バイト数をリアルタイムで表示し、上限を超えた場合は視覚的に警告する。スマホ表示時はレスポンシブな縦並びレイアウトを採用。

### 3.3. 実装の変更箇所

- `src/utils/qr-ticket.ts`:
  - `buildPayload`: `join('|')` ロジックに変更。
  - `estimateTicketByteSize`: 署名込みのバイト数を見積もる共通関数を追加。
  - 定数 `MAX_QR_BYTE_SIZE` (300) を定義。
- `src/components/tools/QrTicket.tsx`:
  - `handleGenerate` で共通関数を使用した厳密なバリデーション。
  - エラーメッセージを「上限を超えているチケットがあります」と簡潔化。
- `src/components/tools/qr-ticket/GenerateTab.tsx`:
  - 合計バイト数のリアルタイム表示。
  - `w-15` 等の Tailwind クラスによるスタイル最適化。

## 4. 検証計画

- **単体テスト**: `src/utils/__tests__/qr-ticket.test.ts` で新形式とサイズ計算を検証。
- **E2Eテスト**: `npm run test:e2e` で生成・検証・バリデーションのフローを確認。
- **目視確認**: Playwright により PC(1280px) とスマホ(390px) でのレイアウトを確認。
