# 日本語ダミー個人データ生成 (`dummy-personal-data`) 設計

- 日付: 2026-06-27
- 候補リスト: `docs/tool-candidates.md` B2-18
- ブランチ: `claude/photo-tool-feasibility-x69ly2`
- 着想元: User Local「個人情報テストデータ生成ツール」のスクリーンショット

## 目的

日本語に特化した架空の個人テストデータ（氏名＋整合フリガナ・性別・生年月日・年齢・郵便番号・住所・電話番号・携帯番号・メールアドレス）を指定件数だけ生成し、CSV / JSON でダウンロードできるツール。開発・検証用のテストデータを手元で安全に量産する用途。

`faker` の ja ロケールはバンドル過大なため不採用とし、自前の軽量辞書＋ `Math.random()` で生成する（既存 `DummyText` と同系統）。全処理ブラウザ内で完結し外部送信しない。生成されるのは架空データのみで実在の個人情報は扱わないため、生成側ツールとして匿名化ツール（候補 S2-3 `csv-anonymizer`）と対になる位置づけ。差別化の主軸は「日本語特化の品質」（氏名↔フリガナの整合・実在しない携帯番号帯・住所↔郵便番号の整合・和暦/西暦の整合した生年月日）。

## スコープ

### v1 に含む（コア9項目）

- 氏名（漢字）: 姓辞書＋名辞書から選択。区切り文字を選択可（半角スペース / 全角スペース / なし）
- フリガナ: 漢字とペアで辞書保持した読み（ひらがな）。漢字と必ず整合
- 性別: `男` / `女` / `その他・不明`（人口比に厳密準拠はせず概ね均等、その他・不明は低確率）
- 生年月日: `YYYY年MM月DD日` 書式。年齢範囲から逆算した実在する日付
- 年齢: 指定範囲（既定 20〜80）で生成。生年月日と整合（基準日は生成時の現在日付）
- 郵便番号: 住所と整合する 7 桁（`NNN-NNNN`）。辞書で都道府県・市区町村とペア保持
- 住所: 都道府県＋市区町村＋丁目・番地・号（番地等はランダム生成）
- 電話番号（固定）: 住所の都道府県に応じた市外局番＋ランダム加入者番号
- 携帯電話番号: 先頭 `0900` / `0700` のいずれかにした 11 桁（第4桁 C=0 固定で音声携帯の割当対象外。後述）
- メールアドレス: ローマ字氏名ベースのローカル部＋ `example.com` / `example.jp` / `example.net` 等（RFC 2606 予約ドメイン＝実在回避）

UI:

- 出力件数（既定 100、上限 3,000）
- 年齢範囲（下限 / 上限）
- 氏名区切り文字の選択
- 各項目の ON/OFF（`ToggleChips`）。氏名は常時 ON
- 出力形式トグル（CSV / JSON）
- 生成結果の先頭 20 件テーブルプレビュー
- ダウンロードボタン（全件）
- 架空データである旨の注意書きバナー

### v1 に含まない（先送り＝必要なら issue 化）

- クレジットカード番号・有効期限・マイナンバー（コア項目のみのスコープ確定により除外。将来 B2-4 `check-digit` の知見で拡張余地）
- 血液型・会社名（スコープ外。拡張余地）
- Excel（.xlsx）出力（`xlsx` / `exceljs` のバンドル増を避ける。CSV は UTF-8 BOM 付きで Excel 互換）
- カタカナ / ローマ字氏名の出力切替（v1 は漢字＋ふりがな固定）
- 人口比・地域分布に厳密準拠した統計的生成（年齢/性別/血液型の人口比重み付け）
- 住所↔郵便番号の網羅的実データ連携（v1 は辞書サンプルセット内での整合に限定）

## 生成ロジック（`generate.ts`）

### 氏名 ↔ フリガナの整合

- 辞書は `{ kanji, yomi }` のペア配列（姓・名それぞれ）。
- 生成時に姓・名を各 1 件選び、漢字は `kanji` を、フリガナは `yomi` を組み合わせる。これにより漢字と読みが必ず一致する。
- メールローカル部用にローマ字（ヘボン式）も辞書に持たせるか、`yomi` から簡易ローマ字変換関数で生成（長音・撥音の最小対応）。v1 は辞書に `romaji` を持たせる方式を採用（変換の曖昧さを回避）。

### 生年月日 ↔ 年齢

1. 年齢を `[ageMin, ageMax]` の一様乱数で決定。
2. 基準日（生成時の現在日付）から「その年齢である誕生日」が成立する生年月日範囲を求め、その範囲で日付をランダム生成。
3. 生成した生年月日から基準日時点の満年齢を再計算し、`age` カラムに格納（端数日で 1 歳ずれないよう、年齢→日付→年齢の往復で確定）。
4. 存在しない日付（2/30 等）は生成しない（月ごとの日数・うるう年を考慮）。

### 住所 ↔ 郵便番号 ↔ 市外局番

- 住所辞書は `{ zip, pref, city, areaCode }` のタプル配列。
- 1 件選ぶと郵便番号・都道府県・市区町村・固定電話の市外局番が同時に確定し、相互に整合する。
- 住所文字列は `pref + city + 丁目・番地・号`（番地等はランダム整数）で組み立てる。

### 携帯電話番号（実在しない確度を優先）

- 先頭 4 桁を `0900` / `0700` のいずれかからランダム選択し、残り 7 桁をランダム数字にした 11 桁。
- 表示は標準の 3-4-4 ハイフン区切り（例 `090-0XXX-XXXX` / `070-0XXX-XXXX`）。
- 方針の根拠（出典: 総務省「電話番号に関する情報」の「電気通信番号の種別」表 https://www.soumu.go.jp/main_sosiki/joho_tsusin/top/tel_number/index.html ）:
  - 音声伝送携帯電話番号（携帯番号）の構成は `0X0CDEFGHJK`（0X0 = 060/070/080/090）で **「C は 0 を除く」**。よって第 4 桁 C を `0` 固定にした番号は、音声携帯として割り当て対象外＝実在しない確度が極めて高い。
  - `0900`（090 + C=0）/ `0700`（070 + C=0）… 上記により音声携帯の割当空間外。かつ他の番号種別にも該当 11 桁の割当が無い。
  - `0800` は除外（フリーダイヤルとして実在）。
  - `0600` は除外（同表に **FMC 電話番号 `0600DEFGHJK`** として割り当て済みの番号種別が存在するため）。
- 桁列 `0900XXXXXXX` は形式上 `090-0XXX-XXXX` と等価だが、上表の「C は 0 を除く」規定により音声携帯の割当対象から外れるため、実在回避の根拠は番号計画上明確。

### 固定電話番号

- 住所辞書で確定した市外局番＋ランダムな市内局番・加入者番号を組み立て、`NN-NNNN-NNNN` 等の桁数に整形（市外局番桁数に応じて区切り位置を調整）。

### メールアドレス

- ローカル部: ローマ字姓・名＋区切り（`.` / `_` / 数字）の組合せでバリエーション生成。
- ドメイン: `example.com` / `example.jp` / `example.net` / `example.org`（RFC 2606 予約）からランダム。実在ドメインは使わない。

## UI / データフロー

- 状態: 生成オプション（件数・年齢範囲・区切り・項目選択・出力形式）。`useClampedInput` で件数・年齢を範囲クランプ。
- 「生成」操作で `generate()` を件数分呼び出し `PersonRecord[]` を作成 → 先頭 20 件をテーブルに表示。
- ダウンロードは `serialize()` で全件を CSV / JSON 化し `download.ts` ユーティリティで保存。CSV は UTF-8 BOM 付き（Excel 互換）。
- 共通 UI（`InputField` / `ToggleGroup` / `ToggleChips` / `DownloadButton` / `NotificationBanner`）と DADS デザイン規約に準拠。
- 色は CSS 変数 / semantic token utility 経由（primitive scale 直書き禁止）。`@layer components` 手書き class への variant prefix は使わない。
- PC（1280x800）/ スマホ（390x844）両対応。テーブルは横スクロール可。

## エラーハンドリング

- 件数・年齢範囲は入力時に上下限へクランプ（`useClampedInput`）。年齢下限 > 上限は入替または案内。
- 全項目 OFF は不可（氏名は常時 ON）。
- 生成 0 件のときはプレビュー・DL を非活性。

## 注意書き（架空データ明示）

- 生成データは開発・検証用の**架空データ**であり実在の個人・連絡先ではない旨を `NotificationBanner` で明示。
- 電話番号・携帯番号は形式的に生成したもので実在を保証しない旨を併記。

## テスト

### ユニット（Vitest）

- 氏名↔フリガナ整合: 生成レコードの漢字と読みが辞書ペアに存在することを assert。**陽性対照**として、不整合なペア（漢字 A ＋別人の読み B）を検証関数に渡すと不一致を検出して fail することを確認（検証ロジックの検知能力を担保）。
- 生年月日↔年齢整合: 生成した生年月日から再計算した満年齢が `age` と一致すること。範囲外年齢は出ないこと。陽性対照: 年齢を 1 ずらした不整合データで検証が fail すること。
- 住所↔郵便番号↔市外局番整合: 生成タプルが辞書に存在する正規の組合せであること。陽性対照: 別タプルの郵便番号を差し替えた不整合データで fail すること。
- 携帯番号: 生成 11 桁が `0900` / `0700` のいずれかで始まり 11 桁であること。第4桁が `0`（音声携帯の割当対象外）であること。陽性対照: 割当済み帯（`0800...`＝フリーダイヤル / `0600...`＝FMC / `09012345678` のような C≠0 の実在帯）を判定関数に渡すと reject すること。
- 件数クランプ: 上限 3,000 / 下限 1 を超える入力がクランプされること。
- シリアライズ: CSV は BOM 付き・選択項目のみ列出力・区切り設定反映。JSON はキー整合。

> ガード / 検証ロジックを含むため `test-gates` skill の陽性対照ルールに従う（検知能力ゼロで green を避ける）。

### E2E（Playwright, preview 経由）

- 件数・年齢を入力 → 生成 → プレビュー行数（先頭 20 件）と項目列を確認。
- 出力形式トグル切替 → ダウンロード操作が発火すること。
- 項目 OFF → プレビュー列が消えること。
- `tests/e2e/visual-regression-pages.ts` の `PAGES` に `/tools/dummy-personal-data` を追加（VRT 対象登録。漏れると `tests/meta/vrt-pages-coverage.test.ts` が fail）。
- VRT baseline は CI Linux runner の `Update Visual Regression Baseline` workflow を `workflow_dispatch` で生成。**web セッションのトークンには `actions: write` が無く自動起動不可**のため、PR ブランチ指定での手動トリガーをユーザーへ依頼する。
